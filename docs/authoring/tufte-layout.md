# Tufte 教学布局作者规范

本文档约束 vault 词条和学习路径页中的四种教学语义：页边图、通栏图表、题记和开篇短语。它们只改变信息组织，不改变词条内容的事实源，也不替代正文中的定义、推导、运行方法和结论。

## 文件边界

词条正文和插图只编辑 vault：

`~/Documents/ObsidianVaults/Main/03 - AREAS/learning/why-models-learn/<slug>.md`

`content-zh/`、`public/assets/` 和 `dist/` 是生成产物。不要手工编辑它们。写作完成后从仓库根目录运行 `npm run sync`。

布局语法使用受限的 Obsidian callout。同步先校验结构，再保留布局标记供 Markdown AST 管线转换。结构错误包含词条文件和起始行号，并在写入任何生成产物前终止同步。

## 页边图 `marginfigure`

页边图用于紧邻正文的小型辅助图。正文必须已经说明图中承载的事实；删除页边图后，正文仍应完整。

```markdown
> [!marginfigure] 三种距离球的轮廓
> ![三种距离球的轮廓对比](svg/lengths-and-distances.1.svg)
```

规则：

- 只放一张图片。
- 使用 `svg/` 下的仓库插图。
- 提供非空 alt 文本。
- 可在图片后增加一行短图注；不要在图片前放图注。
- 不放表格、代码、展示公式、嵌套 callout 或原始 HTML。
- 一篇词条最多使用两个教学布局；超过两个只产生非阻塞 lint，仍需说明必要性。

桌面端图片进入右侧 240 px 页边。窄屏和打印回到正文流，并始终可见。图像仍按源文件的阅读顺序出现在 DOM 中。

### 240 px 可读性判断

先在实际 240 px 页边宽度预览图片，再决定是否使用页边图。满足以下条件才使用 `marginfigure`：

- 图的主要关系不依赖缩放或横向滚动。
- 文字、数字、箭头和图例在默认缩放下可辨认。
- 图注与正文已经说明图的事实，读者不需要从小图中抄取精确数值。
- 浅色与黑色主题下的线条层级仍然清楚。
- 图片回到 390 px 移动正文流后，不造成页面级横向溢出。

校准批次进一步确认：含两个以上区域、坐标轴、公式标签、三步以上流程或多组数值的图，默认不能进入页边。只有在 240 px 下无需缩放即可读出全部教学标签时，才可以例外使用 `marginfigure`。

如果读者需要放大才能识别标签，保留为正文插图。如果图是主论证的核心流程或包含密集标注，使用正文宽度；只有正文宽度仍不足时才考虑通栏。

## 通栏图表 `fullwidth`

通栏只用于 680 px 正文列无法清晰容纳的核心图或表。先确认缩窄到正文列会损失列名、比较关系或图中标注，再使用通栏。不要为了装饰扩大普通段落。

表格模式：

```markdown
> [!fullwidth] 比较表
> | 条件 | 结果 | 解释 |
> | --- | --- | --- |
> | 小批量 | 噪声较大 | 更新次数更多 |
```

图片模式：

```markdown
> [!fullwidth] 训练流程
> ![从前向传播到参数更新的流程](svg/example.1.svg)
```

规则：

- 一个通栏只能选择一张图片或一张表格，不能混合。
- 表格必须有分隔行，所有行的列数必须一致。
- 图片模式只能包含一张 `svg/` 图片，并提供非空 alt 文本。
- 不放额外段落、代码、展示公式、嵌套 callout 或原始 HTML。

桌面端通栏可以使用正文和页边的总宽。移动端表格只在自身容器内滚动，不能造成页面根节点横向溢出。打印端取消浮动和最小宽度，表格按纸张可用宽度排版。

### 680 px 通栏证据

通栏决定必须先观察 680 px 正文列。以下任一现象可以作为使用 `fullwidth` 的证据：

- 核心比较列需要横向滚动后才能同时阅读。
- 列名或单元格换行破坏逐行比较关系。
- 图中关键标注重叠、被裁切或缩小到不可辨认。
- 流程图被迫分行后改变阅读顺序。

列数多、图片原始尺寸大或文章很长都不是充分理由。普通表格在正文列内可读时保持现状。批次 QA 必须记录正文列观察结果和采用通栏的具体原因。

## 题记 `epigraph`

题记只用于学习路径页或章节开场的短引文。来源必须可识别，必要的定义和论证不能只放在题记中。

```markdown
> [!epigraph]
> 「先建立可运行的直觉，再回看完整证明。」
>
> ——学习路径说明
```

题记必须包含一段引文、一个空行和最后一行来源。词条中段的题记会产生非阻塞 lint。普通 Markdown 引用不使用该标记，因此继续保持原有渲染。

## 开篇短语 `newthought`

开篇短语只由 `/learn/` 学习路径页生成，用于阶段导语。词条正文不使用行内 DSL，也不把 `newthought` 当作标题或 `##` 分节替代物。

## 可访问性与删除检查

- 保持图片 alt 的事实描述，避免使用“见图”或空字符串。
- 保持语义元素和 DOM 顺序，不依赖 CSS 阅读顺序传递必要信息。
- 不加入折叠、checkbox toggle 或布局 JavaScript。
- 在浅色、黑色、移动、打印和 `prefers-reduced-motion: reduce` 环境中确认内容可见。
- 临时删除全部布局包装后，确认正文、学习路径、导航和交叉链接仍然成立。

逐篇删除检查使用以下记录：

```markdown
- 删除对象：旁注 / 页边图 / 通栏 / 题记
- 正文仍保留的定义：
- 正文仍保留的推导或证据：
- 正文仍保留的结论：
- 结果：通过 / 不通过
```

结果为“不通过”时，把承重内容移回正文，再重新判断布局职责。不能通过增加另一条旁注修补正文缺口。

## 提交前检查

```bash
npm run sync
npm test
npm run build
git diff --check
```

浏览器验收至少覆盖 `playground`、`/learn/`、一篇数学词条和一篇模型词条。记录桌面端 1440 px、移动端 390 px、浅色、黑色和打印结果。没有可用浏览器时，不得把 CSS 单元测试写成浏览器实测结论；在 QA 记录中标记未验证边界。

逐篇优化使用 `docs/qa/tufte-optimization/manifest.yaml` 记录决定，使用 `docs/qa/tufte-optimization/batch-template.md` 记录批次证据。含宽公式、宽表或密集图的词条增加 320 px 压力检查。

大纲新增已完成词条后运行 `make tufte-manifest`。该命令保留已有审查记录，只追加新词条；遇到被移除的记录或学习角色变化时停止并要求人工裁决。
