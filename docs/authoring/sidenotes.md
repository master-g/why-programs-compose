# 旁注作者规范

本文档约束 vault 词条中的编号旁注与无编号边注。旁注用于补充局部术语、限定条件、来源或短提醒。删除全部旁注后，正文的定义、推导、论证、运行方法和结论必须保持完整。

## 文件边界

只编辑 vault 中的源词条：

`~/Documents/ObsidianVaults/Main/03 - AREAS/learning/why-models-learn/<slug>.md`

`content-zh/` 是 `npm run sync` 生成的产物。不要手工编辑生成词条。

## 编号旁注

编号旁注使用 Markdown 脚注。引用放在需要精确对应的正文位置，定义使用同一个唯一 ID：

```markdown
欧几里得范数来自内积。[^inner-product]

[^inner-product]: 这条构造得到 2-范数；参见[[inner-products|内积]]与 $p=2$。
```

每个 ID 必须恰好有一个引用和一个定义。不要在同一篇词条中重复引用同一个 ID。站点按引用顺序自动编号，作者不要手写编号。

## 无编号边注

无编号边注使用紧跟正文段落的 `marginnote` callout：

```markdown
范数下标指定距离规则。

> [!marginnote] 符号提醒
> 下标表示使用的范数；参见[[norms|范数]]与 $p$。
```

标签不能为空。边注必须紧跟普通正文段落。不要把边注放在标题、列表、表格或代码块之后。

## 内容边界

旁注只允许以下内容：

- 纯文本与强调。
- 站内链接与站外链接。
- 行内数学。

旁注禁止以下内容：

- 展示公式。
- 表格与代码。
- 图片。
- 嵌套 callout。
- 多段块内容。
- 原始 HTML。

单篇超过 6 条旁注或单条超过 120 个可见字符时，同步产生 `SIDENOTE-LINT` 警告。该警告不阻止同步。结构错误产生 `SIDENOTE-ERROR`，同步在写入任何生成产物前终止。

## 选择规则

先确认补充信息是否可以从正文移除。定义、推导步骤、数字例子、实验结论和操作指令必须留在正文。

按以下顺序选择：

1. 读者第一遍必须理解时，保留在正文。
2. 补充信息需要与一句正文精确对应，并需要引用与返回锚点时，使用编号旁注。
3. 补充信息是局部术语提醒、限定条件或第一遍阅读边界，不需要编号时，使用无编号边注。
4. 补充信息需要图片、表格或展示公式时，不使用旁注。图片和宽表按 `tufte-layout.md` 判断，完整推导保留在正文。
5. 不能说明独立教学职责时，保持现状。

编号旁注与无编号边注都不是正文压缩工具。不要把连续两段正文拆成多个短旁注，也不要在页边重复正文原句。

## 正反例

适合编号旁注：

```markdown
有限维空间中的所有范数给出相同的收敛概念。[^norm-equivalence]

[^norm-equivalence]: 等价常数依赖维数与所比较的范数；这里不讨论无限维空间。
```

这条信息限定一句结论，并需要精确往返。

适合无编号边注：

```markdown
梯度的坐标取决于当前基底。

> [!marginnote] 第一遍边界
> 先把梯度理解为最陡上升方向；坐标变换在[[change-of-basis|基变换]]中处理。
```

这条信息划定第一遍阅读深度，删除后正文定义仍成立。

保持现状：一段正文依次给出随机变量的定义、取值和一个掷骰子例子。三项内容共同构成首次理解，不能因为篇幅较长而把例子移入页边。

错误用法：把损失函数的适用条件、公式和最终结论全部放入一条旁注。正文会在删除旁注后失去论证，因此必须改回正文。

## 与教学布局的边界

页边图、通栏图表和题记使用独立的 `marginfigure`、`fullwidth` 与 `epigraph` 语法，规范见 [Tufte 教学布局作者规范](tufte-layout.md)。不要把图片、表格或展示公式塞进旁注，也不要用旁注承载学习路径的必要前置。

同步会先保留并校验这些布局，再执行旁注校验。普通 callout 仍按原有规则降级；布局 callout 不会被旁注清理逻辑误删。两类内容都必须遵守“删除呈现增强后正文仍然自足”的要求。

## 响应式行为

桌面端把两类旁注放入 240 px 右侧页边，并按文档顺序向下排列。移动端把旁注放回引用附近的正文流并始终显示。页面不使用复选框、折叠状态或旁注 JavaScript。

编号引用和返回链接支持锚点往返。无编号边注使用作者标签，不占用编号序列。

## 提交前检查

从仓库根目录运行：

```bash
npm run sync
npm test
npm run build
```

再在 `playground` 与新增旁注词条中检查桌面端、移动端、白色主题和黑色主题。确认旁注可见、顺序正确、没有重叠或页面级横向溢出。

逐篇优化时还要在 `docs/qa/tufte-optimization/manifest.yaml` 记录采用决定或保持现状理由。批次证据使用 `docs/qa/tufte-optimization/batch-template.md`。

大纲新增已完成词条后运行 `make tufte-manifest`。该命令保留已有审查记录，只追加新词条；遇到被移除的记录或学习角色变化时停止并要求人工裁决。
